# Input datasets

All 120 supplied CSV/JSON files are preserved under `generated_inputs/`:
three network sizes, ten configurations per size, and four files per configuration.
`inputs_D5`, `inputs_D10`, and `inputs_D15` duplicate the baseline files for the
existing study runner's expected input layout.

| File | Contents |
| --- | --- |
| `case.json` | Source device, operator count, memory/protocol policies, solver options, model quota, and provenance notes |
| `devices.csv` | Device IDs/types, memory capacities/reservations, arena pool, compute coefficients, and supported protocols |
| `segments.csv` | Original hosts, operator ranges, activation volumes, model sizes, and runtime memory components |
| `links.csv` | Directed endpoint/protocol combinations and effective throughput in bytes per second |

Failure combinations are generated by `failure_scenarios()` in `solve_milp.py`;
a separate `failures.csv` is not needed. Each run preserves the original primary
deployment and independently selects the failed set. The data-acquisition device
does not fail.

## Link-rate configurations

Each `D5`, `D10`, or `D15` directory contains `baseline` and nine folders named
`rate_{25,50,75}_seed_{2026,2027,2028}`.

For reduction bound `level`, the supplied implementation uses:

```text
B_new(i,j,p) = B_baseline(i,j,p) * (1 - level * u)
u = deterministic SHA-256-derived value in [0, 1)
```

The hash keys include the link seed, network size, unordered endpoint pair, and
protocol. Reciprocal entries therefore receive the same multiplier. A 75% level
means each link loses between zero and approximately 75% of its original rate;
it does not mean every link retains exactly 25% of its rate. Link availability
and protocol compatibility are unchanged.

The input notes include historical references to earlier formulations. The
effective fields select `protocol_policy: joint` and `memory_policy: esp32_psram`.
These notes have been retained as supplied, alongside the original data values.
